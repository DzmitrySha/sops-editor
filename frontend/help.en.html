SOPS Editor — what to do

RUEN ← Back to editor

The tool decrypts a SOPS file in memory, lets you edit secrets and saves it back encrypted with the same recipients and rules. Below: connecting sops, keys, every workflow and the usual problems.

1. Connecting SOPS

The app needs two executables: sops (encryption/decryption) and, preferably, age-keygen (key validation). Plus the private key that the file was encrypted for.

Option A. Docker (recommended)

The image already ships sops 3.13.3 and age 1.3.2 — nothing to install. Check the badge in the header: “sops …” shows the version, “sops unavailable” shows an error.

# Windows: start-windows.cmd   (or the shortcut from windows\install-shortcut.ps1)
# Linux:
docker compose --env-file docker/.env --env-file docker/.env.secrets up -d --build
curl -s http://localhost:8787/api/health      # {"status":"ok","sops":"sops 3.13.3"}

Option B. Without Docker (Windows, local development)

  1. Put sops.exe and age\age-keygen.exe into the project’s .tools\ directory (or add them to PATH).
  2. Create a virtualenv and install dependencies: .venv\Scripts\pip install -e "backend[test]".
  3. Start the server with roots and the key:
set SOPS_EDITOR_ROOTS=D:\repo|D:\tmp\repos
set SOPS_EDITOR_STORAGE=D:\sops-data
set SOPS_AGE_KEY_FILE=D:\keys\age.txt
set SOPS_EDITOR_SOPS_BIN=D:\project\.tools\sops.exe
set SOPS_EDITOR_AGE_KEYGEN_BIN=D:\project\.tools\age\age-keygen.exe
cd backend
..\.venv\Scripts\python -m uvicorn app.main:create_app --factory --port 8787

Option C. System-wide install

# Windows (winget / scoop / choco)
winget install --id GetsOps.SOPS
# Linux (deb/rpm from the releases page), or:
curl -fsSL -o /usr/local/bin/sops https://github.com/getsops/sops/releases/download/v3.13.3/sops-v3.13.3.linux.amd64
chmod +x /usr/local/bin/sops
sops --version

If sops is not in PATH, set the full path via SOPS_EDITOR_SOPS_BIN (and SOPS_EDITOR_AGE_KEYGEN_BIN for age-keygen).

Encryption rules (.sops.yaml)

SOPS takes recipients from .sops.yaml at the repository root or from the file’s own metadata. The app never changes recipients: saving goes through sops edit, so keys, MAC and encrypted_regex stay as they were.

# .sops.yaml
creation_rules:
  - path_regex: .*\.enc\.yaml$
    age: age1ql3z7hjy54pw3hyww5ayyfg7zqgvc7w3j2elw8zmrj2kg5sfn9aqmcac8p

Encrypt an existing file

sops --encrypt --in-place secrets.yaml          # uses .sops.yaml
sops --encrypt --age age1... --in-place secrets.yaml
sops --decrypt secrets.yaml                     # verify the key fits
sops filestatus secrets.yaml                    # {"encrypted": true, ...}

Plain files can be opened in the editor too; the “Encrypt” button creates the SOPS version. Encrypted files with unusual names (e.g. .env_enc.test) are detected by their content.

2. Keys: which one is used

Key selection, from highest to lowest priority:

SourceHow to setScope
Tab key“Key” button → paste AGE-SECRET-KEY-1…Process memory, TTL 8 h, tab cookie

Default key~/.config/sops/age/keys.txtContainer user

Generate a new pair:

age-keygen -o keys/age.txt
grep 'public key' keys/age.txt          # age1… — add it to .sops.yaml
# private key — only in keys/age.txt (mounted read-only) or in env

In Docker the keys directory is mounted read-only: SOPS_EDITOR_KEYS=./keys. If the file is missing, the app starts without a server key and offers to enter one in the UI.

A key entered in the UI lives only in process memory and is never written to disk or logs. “Forget key” removes it immediately. The tab key takes precedence over the server key: while it is set, the server key is not used.

2.1. Files exist, no key

This is not a bug. A SOPS file contains only public recipients; the private key is not inside. Without the private key of at least one recipient decryption is impossible — it cannot be brute-forced, that is the point of encryption.

Step 1. Find out which key is needed

  • Open the file in the app — the “Key” window lists age: age1…, PGP: fingerprint or the provider (KMS/Vault).
  • In a terminal: sops filestatus file or simply sops -d file — the error names the recipients.
  • The metadata is in the file’s own sops: section — it is not secret.

Step 2. Find the recipient’s private key

TypeWhere to look
agekeys/age.txt, SOPS_AGE_KEY, SOPS_AGE_KEY_FILE, ~/.config/sops/age/keys.txt, *.agekey, password manager; the machine that encrypted the file; CI/CD secrets; the colleague who granted access.
PGPSecret key in GnuPG: gpg --list-secret-keys --keyid-format long. Must be on the server/container (gpg-agent); the UI “Key” field accepts age keys only.
KMS / VaultNo private key: the server process needs cloud permissions (IAM role, Vault token).

Step 3. Verify the key before uploading

age -d -i keys/age.txt secrets.enc.yaml          # age
SOPS_AGE_KEY_FILE=keys/age.txt sops -d secrets.enc.yaml
gpg --decrypt secrets.enc.yaml                    # PGP, if the key is in the keyring

If the command prints plaintext, the same key file works for the app: put it in keys/age.txt, set SOPS_AGE_KEY_FILE or paste the key into the “Key” window.

If the key is gone

  • Recovering a ciphertext without the recipient’s key is impossible — neither with this tool, nor sops, nor updatekeys/rotate.
  • Look for plaintext sources: old branches/tags, backups, another person/machine, CI artifacts — and encrypt again with a new key.
  • A new key added to keys/age.txt or the UI changes nothing: recipients are recorded in the file. To add a recipient you need access with an old key: add it to .sops.yaml and run sops updatekeys file.
  • Keep a backup of the key: age-keygen -o once, at least two copies.

3. File from your computer (local git clone)

  1. Open the “From computer” tab.
  2. Press “Choose file” (standard browser dialog — always works) or drag a file into the drop zone. A status line appears under the button: name, size, stage (“Uploading…” / error / “opened”). An unencrypted YAML/JSON/dotenv/INI file also opens in the editor; the “Encrypt” button in the editor creates the SOPS version.
  3. If there is no server key, the “Key” window opens — paste your AGE-SECRET-KEY-1… (or load a .txt with the key). The file opens automatically afterwards.
  4. Edit the secrets and press “Save” (Ctrl+S). The server encrypts and verifies the result.
  5. Take the result: “Download encrypted” — the browser saves the file under its original name; “Write to source file” — in Chrome/Edge writes the ciphertext straight into the chosen file and asks only for overwrite confirmation (no second location prompt).

Direct writing requires the browser to remember the file. The “Allow overwriting the file…” button in the left panel asks you to pick the same file once — the handle is kept until the tab is reloaded; after that “Write to source file” only asks for confirmation. If the browser does not support the API, only “Download encrypted” and manual replacement are available.

What happens on the server: the uploaded file is stored in /data/uploads/<tab id>/<random dir>/name, decrypted in memory, and after saving downloaded back already encrypted. Directories older than 7 days are removed automatically.

Browser limitation: the full local path is not exposed, so the tool works with the chosen file, not the whole folder. For a repository, mount it into /workspace.

4. File on the server

  • Path manually: /workspace/secrets/app.enc.yaml — a path inside the container.
  • Browse: “Browse” opens the tree of allowed directories; double-click to enter/open, “Search the tree” to find by name.
  • From git: the “From git” tab → URL and branch → “Clone to /data/repos”. The directory browser opens right after cloning.

Allowed directories are set by SOPS_EDITOR_ROOTS (separated by |) and listed on the start screen; clicking one opens the browser.

5. Encrypt a file from scratch

Open a plain YAML/JSON/dotenv/INI file (server, git or computer) — it opens in the editor. Press “Encrypt” in the editor toolbar: the server runs sops encrypt and creates a sibling file (secret.yaml → secret.enc.yaml); the original stays untouched. The encrypted file opens right away.

Recipients

  • Empty — use the nearest .sops.yaml rule; if there is no rule, the server (or session) key.
  • Custom — one or more public age1… keys, comma/newline separated. No private key is needed: encryption uses public recipients only.
  • The private key from the “Key” window becomes the default recipient automatically — the file opens in the editor immediately.

The file is encrypted on the server and only ciphertext remains: plaintext is removed from the uploaded file right after encryption. The source file on your computer is unchanged: take the result with “Download encrypted” / “Write to source file”.

Terminal equivalent:

sops --encrypt --age age1… --input-type yaml --output-type yaml secret.yaml > secret.enc.yaml
# or with repository rules:
sops --encrypt --filename-override secret.enc.yaml secret.yaml > secret.enc.yaml

7. How saving works

  1. The server compares the SHA-256 of the submitted ciphertext with the current file — protection against overwriting someone else’s edit (409 conflict).
  2. Creates a ciphertext backup in /data/backups/<hash>/ (10 per file by default).
  3. Writes the plaintext into a temporary 0600 file in a private directory and runs sops edit with a one-shot “editor”; SOPS re-encrypts with the original metadata and updates the MAC.
  4. Decrypts the result again and compares the data with what was submitted; on mismatch the original ciphertext is restored atomically.
  5. The temporary plaintext is removed in finally.

The file on disk is either the old or the new ciphertext at any moment. Plaintext is never written to disk.

9. Troubleshooting

SymptomCause and fix
Chose a file — nothing happensThe dialog was closed or the file was not selected. The status line under the button always shows the reason now. Use “Choose file” (standard dialog, always works) or drag the file.
“The file is not SOPS-encrypted”Plain files open in the editor now; press “Encrypt” to create the SOPS version. Encrypted files with unusual names (e.g. .env_enc.test) are detected by content.
“Private key” window after choosingThe server cannot decrypt the file: no matching key. Paste AGE-SECRET-KEY-1…, put keys/age.txt in place or check SOPS_AGE_KEY_FILE.
“The key does not match this file”The file is encrypted for another recipient. Check sops -d with this key and .sops.yaml.
“sops unavailable” in the headerThe container lacks the binary (wrong image) or SOPS_EDITOR_SOPS_BIN is wrong. Check /api/health.
Opening or saving takes longThe operation runs on the server: the progress window shows a spinner, elapsed time and the step list (path → read → SOPS metadata → sops decrypt → format → git). If the time runs but steps do not move, the delay is the network/proxy between the browser and the server — wait for the reply, do not close the tab. Excluding localhost/127.0.0.1 from a filtering proxy (e.g. AdGuard) removes the first-request stall.
409 “The file changed”The file was overwritten by another process/person. Press “Reload” — editor changes will be lost (copy them first if needed).
413 “File is too large”The SOPS_EDITOR_MAX_FILE_BYTES limit (5 MiB by default). Raise it.
“Could not write the file”The browser denied write permission or the file is unavailable. Use “Download encrypted” and replace the file manually.
The file disappeared from “Download”Upload directories older than 7 days are removed. Upload the file from your computer again.
Push failsNo remote or credentials: set SOPS_EDITOR_GIT_TOKEN or mount an SSH key.

10. Limits

  • Formats: YAML, JSON, dotenv, INI. Binary SOPS files (archives, arbitrary data) are not supported.
  • Recipients and KMS policy are not changed: use sops updatekeys/rotate for rotation.
  • No multi-user model: Basic auth plus one server key or per-tab keys in memory.
  • Plaintext passes through the server (in memory) — open the tool over HTTPS or on localhost.
  • Building the Docker image needs internet (sops/age/pip).
