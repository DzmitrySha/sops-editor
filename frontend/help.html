SOPS Editor — что делать

RUEN ← К редактору

Утилита расшифровывает SOPS-файл в памяти, даёт отредактировать секреты и сохраняет обратно с теми же получателями и правилами. Ниже — подключение sops, ключи, все сценарии и разбор типичных проблем.

1. Как подключить SOPS

Приложению нужны два исполняемых файла: sops (шифрование/расшифровка) и, желательно, age-keygen (проверка ключа). Плюс приватный ключ, которым зашифрован сам файл.

Вариант A. Docker (рекомендуется)

В образе уже стоят sops 3.13.3 и age 1.3.2 — ничего устанавливать не нужно. Проверьте на странице запуска: бейдж «sops …» в шапке показывает версию, «sops недоступен» — ошибку.

# Windows: start-windows.cmd   (или ярлык из windows\install-shortcut.ps1)
# Linux:
docker compose --env-file docker/.env --env-file docker/.env.secrets up -d --build
curl -s http://localhost:8787/api/health      # {"status":"ok","sops":"sops 3.13.3"}

Вариант B. Запуск без Docker (Windows, локальная разработка)

  1. Положите sops.exe и age\age-keygen.exe в каталог .tools\ проекта (или добавьте их в PATH).
  2. Создайте виртуальное окружение и поставьте зависимости: .venv\Scripts\pip install -e "backend[test]".
  3. Запустите сервер, указав корни и ключ:
set SOPS_EDITOR_ROOTS=D:\repo|D:\tmp\repos
set SOPS_EDITOR_STORAGE=D:\sops-data
set SOPS_AGE_KEY_FILE=D:\keys\age.txt
set SOPS_EDITOR_SOPS_BIN=D:\project\.tools\sops.exe
set SOPS_EDITOR_AGE_KEYGEN_BIN=D:\project\.tools\age\age-keygen.exe
cd backend
..\.venv\Scripts\python -m uvicorn app.main:create_app --factory --port 8787

Вариант C. Установка sops в систему

# Windows (winget / scoop / choco)
winget install --id GetsOps.SOPS
# Linux (deb/rpm берутся со страницы релизов), либо:
curl -fsSL -o /usr/local/bin/sops https://github.com/getsops/sops/releases/download/v3.13.3/sops-v3.13.3.linux.amd64
chmod +x /usr/local/bin/sops
sops --version

Если sops лежит не в PATH, задайте полный путь через SOPS_EDITOR_SOPS_BIN (и SOPS_EDITOR_AGE_KEYGEN_BIN для age-keygen).

Правила шифрования (.sops.yaml)

SOPS берёт получателей из .sops.yaml в корне репозитория или из метаданных самого файла. Приложение не меняет получателей: сохранение идёт через sops edit, поэтому ключи, MAC и encrypted_regex остаются прежними.

# .sops.yaml
creation_rules:
  - path_regex: .*\.enc\.yaml$
    age: age1ql3z7hjy54pw3hyww5ayyfg7zqgvc7w3j2elw8zmrj2kg5sfn9aqmcac8p

Зашифровать существующий файл

sops --encrypt --in-place secrets.yaml          # с учётом .sops.yaml
sops --encrypt --age age1... --in-place secrets.yaml
sops --decrypt secrets.yaml                     # проверить, что ключ подходит
sops filestatus secrets.yaml                    # {"encrypted": true, ...}

Загружать в утилиту можно только файлы, которые уже являются SOPS-шифротекстом. Обычный YAML сервер отклонит с ошибкой «Файл не зашифрован SOPS».

2. Ключи: какой используется

Порядок выбора ключа — от самого приоритетного к последнему:

ИсточникКак задатьОбласть
Ключ вкладкиКнопка «Ключ» → вставить AGE-SECRET-KEY-1…Память процесса, TTL 8 ч, cookie вкладки
Файл сервераkeys/age.txt → /keys/age.txt, либо SOPS_AGE_KEY_FILEВсе пользователи экземпляра
Ключ по умолчанию~/.config/sops/age/keys.txtПользователь контейнера
ОкружениеSOPS_AGE_KEY, PGP/KMS/Vault-переменныеПроцесс сервера

Сгенерировать новую пару:

age-keygen -o keys/age.txt
grep 'public key' keys/age.txt          # age1… — добавить в .sops.yaml
# приватный ключ — только в keys/age.txt (монтируется read-only) или в env

В Docker каталог ключей монтируется read-only: SOPS_EDITOR_KEYS=./keys. Если файла нет, приложение стартует без серверного ключа и предложит ввести ключ в UI.

Ключ, введённый в UI, живёт только в памяти процесса и не пишется на диск и в логи. Кнопка «Забыть ключ» удаляет его немедленно. Ключ вкладки приоритетнее серверного: пока он задан, серверный ключ не используется.

2.1. Файлы есть, ключа нет

Это не сбой утилиты. Файл SOPS содержит только публичные получатели; приватного ключа в нём нет. Без приватного ключа хотя бы одного получателя расшифровка невозможна — подобрать его нельзя, это и есть защита.

Шаг 1. Узнать, какой ключ нужен

  • В утилите откройте файл — окно «Ключ» покажет: age: age1…, PGP: отпечаток или провайдера (KMS/Vault).
  • В терминале: sops filestatus файл или просто sops -d файл — в ошибке будет список получателей.
  • Метаданные лежат в самом файле в секции sops: — это не секрет.

Шаг 2. Найти приватный ключ получателя

ТипГде искать
agekeys/age.txt, SOPS_AGE_KEY, SOPS_AGE_KEY_FILE, ~/.config/sops/age/keys.txt, *.agekey, менеджер паролей; машина, на которой файл шифровали; секреты CI/CD; коллега, который выдавал доступ.
PGPСекретный ключ в GnuPG: gpg --list-secret-keys --keyid-format long. Должен быть на сервере/в контейнере (gpg-агент); в окно «Ключ» вставляется только age-ключ.
KMS / VaultПриватного ключа нет: нужны права в облаке (IAM-роль, токен Vault) у процесса сервера.

Шаг 3. Проверить ключ до загрузки

age -d -i keys/age.txt secrets.enc.yaml          # age
SOPS_AGE_KEY_FILE=keys/age.txt sops -d secrets.enc.yaml
gpg --decrypt secrets.enc.yaml                    # PGP, если ключ в связке

Если команда печатает открытый текст — этот же файл ключа подойдёт утилите: положите его в keys/age.txt, задайте SOPS_AGE_KEY_FILE или вставьте ключ в окно «Ключ».

Если ключа нет нигде

  • Восстановить шифротекст без ключа получателя невозможно — ни утилитой, ни sops, ни через updatekeys/rotate.
  • Ищите открытые исходники: старые ветки/теги, бэкапы, другой человек/машина, артефакты CI — и зашифруйте заново новым ключом.
  • Новый ключ, добавленный в keys/age.txt или в UI, ничего не даст: получатели записаны в файле. Чтобы добавить нового получателя, нужен доступ старым ключом: добавьте его в .sops.yaml и выполните sops updatekeys файл.
  • Планово проверяйте, что ключ есть в бэкапе: age-keygen -o один раз, а копий — минимум две.

3. Файл с компьютера (локальный git-клон)

  1. Откройте вкладку «С компьютера».
  2. Нажмите «Выбрать файл» (стандартный диалог браузера — работает всегда) или перетащите файл в область выбора. Под кнопкой появится строка состояния: имя, размер, этап («Загружаем…» / ошибка / «открыт»). Можно выбрать и незашифрованный YAML/JSON/dotenv/INI — он откроется в редакторе, а кнопка «Зашифровать» в редакторе создаст SOPS-версию.
  3. Если серверного ключа нет, откроется окно «Ключ» — вставьте свой AGE-SECRET-KEY-1… (или загрузите .txt с ключом). После сохранения файл откроется автоматически.
  4. Отредактируйте секреты и нажмите «Сохранить» (Ctrl+S). Сервер зашифрует и проверит результат.
  5. Заберите результат: «Скачать зашифрованный» — браузер сохранит файл с исходным именем; «Записать в исходный файл» — в Chrome/Edge пишет шифротекст прямо в выбранный файл и спрашивает только подтверждение перезаписи (без повторного выбора места).

Прямая запись требует, чтобы браузер запомнил файл. Кнопка «Выбрать с перезаписью…» открывает системный диалог Chrome/Edge и сохраняет дескриптор файла до перезагрузки вкладки — тогда «Записать в исходный файл» спрашивает только подтверждение. Если этот диалог в вашей сборке не открывается, используйте «Выбрать файл» (обычный диалог) и «Разрешить перезапись файла…» в панели, либо скачивание. Ошибка системного диалога теперь показывается в строке состояния.

Что происходит на сервере: шифротекст сохраняется в /data/uploads/<id вкладки>/<случайный каталог>/имя, расшифровывается в памяти, а после сохранения скачивается обратно уже зашифрованным. Каталоги старше 7 дней удаляются автоматически.

Ограничение браузера: полный локальный путь недоступен, поэтому утилита работает с выбранным файлом, а не с целой папкой. Для работы с репозиторием смонтируйте его в /workspace.

4. Файл на сервере

  • Путь вручную: /workspace/secrets/app.enc.yaml — путь внутри контейнера.
  • Обзор: кнопка «Обзор» открывает дерево разрешённых каталогов; двойной клик — вход/открытие, «Искать по дереву» — поиск по именам.
  • Из git: вкладка «Из git» → URL и ветка → «Клонировать в /data/repos». После клонирования сразу откроется обзор.

Разрешённые каталоги задаются SOPS_EDITOR_ROOTS (через |) и показываются на главном экране; по клику открывается обзор.

3.1. Зашифровать файл с нуля

Утилита умеет не только редактировать существующие SOPS-файлы, но и шифровать открытые YAML/JSON/dotenv/INI.

Откуда файлКак запустить
С компьютераВкладка «С компьютера» → «Зашифровать обычный файл…» → выбрать файл → проверить получателей → «Зашифровать». Также можно просто перетащить обычный файл: в ответ на «Файл не зашифрован SOPS» появится кнопка «Зашифровать этот файл…».
На сервере«Обзор» → выбрать открытый файл → внизу окна «Зашифровать…». Результат создаётся рядом: secret.yaml → secret.enc.yaml (исходник не меняется).

Получатели

  • Пусто — для файла на сервере берутся правила ближайшего .sops.yaml; если правила нет — серверный (или сессионный) ключ.
  • Свои ключи — вставьте один или несколько публичных age1… через запятую/перенос строки. Приватный ключ не нужен: шифрование использует только публичные получатели.
  • Приватный ключ из окна «Ключ» автоматически становится получателем по умолчанию — файл сразу открывается в редакторе.

Загруженный открытый файл живёт только во временном каталоге 0600 и удаляется сразу после шифрования; на диск попадает только шифротекст. Исходник на компьютере не меняется: результат забирается кнопками «Скачать зашифрованный» / «Записать в исходный файл».

Эквивалент в терминале:

sops --encrypt --age age1… --input-type yaml --output-type yaml secret.yaml > secret.enc.yaml
# или по правилам репозитория:
sops --encrypt --filename-override secret.enc.yaml secret.yaml > secret.enc.yaml

5. Git

КнопкаЧто делает
Коммитgit add -- файл + git commit -- файл; в коммит попадает только открытый файл. Галочка «запушить» делает push после коммита.
↻ (pull)git pull --ff-only, только при чистом рабочем дереве. После pull файл перезагружается.
Из gitgit clone в /data/repos/<имя>.

Для приватных HTTPS-репозиториев задайте SOPS_EDITOR_GIT_TOKEN (GitLab: oauth2, GitHub: x-access-token); токен не передаётся из UI. Для SSH смонтируйте ключ или агент. Хосты клонирования можно ограничить через SOPS_EDITOR_GIT_ALLOWED_HOSTS.

6. Как сохраняется файл

  1. Сервер сверяет SHA-256 присланного шифротекста с текущим файлом — защита от перезаписи чужой правки (409 conflict).
  2. Создаёт резервную копию шифротекста в /data/backups/<hash>/ (по умолчанию 10 на файл).
  3. Кладёт открытый текст во временный файл 0600 в приватном каталоге и запускает sops edit с one-shot «редактором»; SOPS сам перешифровывает файл с метаданными исходника и обновляет MAC.
  4. Повторно расшифровывает результат и сравнивает данные с отправленными; при расхождении атомарно возвращает исходный шифротекст.
  5. Временный открытый текст удаляется в finally.

На диске в любой момент лежит либо старый, либо новый шифротекст. Открытый текст на диск не пишется.

8. Типичные проблемы

СимптомПричина и решение
Выбрал файл — «ничего не происходит»Файл не выбран (диалог закрыт) или файл не является SOPS-шифротекстом. Теперь под кнопкой всегда видна строка состояния и причина. Если выбрано окно Windows — повторите выбор через «Выбрать файл»; диалог всегда стандартный.
Файл не зашифрованЭто нормально: открытый файл откроется в редакторе, а «Сохранить» запишет его как есть. Нажмите «Зашифровать» в редакторе, чтобы получить SOPS-версию. Зашифрованный файл с нестандартным именем (например, .env_enc.test) распознаётся по содержимому.
Окно «Приватный ключ» после выбораСервер не может расшифровать файл: нет подходящего ключа. Вставьте AGE-SECRET-KEY-1…, положите keys/age.txt или проверьте SOPS_AGE_KEY_FILE.
«Ключ не подходит для этого файла»Файл зашифрован на другого получателя. Проверьте sops -d с этим ключом и .sops.yaml.
«sops недоступен» в шапкеВ контейнере нет бинарника (запущен не тот образ) или неверный SOPS_EDITOR_SOPS_BIN. Проверьте /api/health.
Долго открывается или сохраняетсяОперация идёт на сервере: в окне прогресса видны спиннер, прошедшее время и список этапов (проверка пути → чтение → SOPS-метаданные → sops decrypt → формат → git). Если время идёт, а этапы не двигаются, задержка в сети/прокси между браузером и сервером — дождитесь ответа, вкладку не закрывайте.
409 «Файл изменился»Файл перезаписан другим процессом/человеком. Нажмите «Перезагрузить» — изменения из редактора будут потеряны (или скопируйте их заранее).
413 «Файл слишком большой»Лимит SOPS_EDITOR_MAX_FILE_BYTES (по умолчанию 5 МиБ). Увеличьте лимит.
«Не удалось записать файл»Браузер не дал разрешение на запись или файл недоступен. Используйте «Скачать зашифрованный» и замените файл вручную.
Файл пропал из «Скачать»Каталог загрузок старше 7 дней удаляется. Загрузите файл с компьютера снова.
Push не выполняетсяНет remote или учётных данных: задайте SOPS_EDITOR_GIT_TOKEN либо смонтируйте SSH-ключ.

9. Ограничения

  • Форматы: YAML, JSON, dotenv, INI. Бинарные SOPS-файлы (архивы, произвольные данные) не поддерживаются.
  • Получатели и KMS-политика не меняются: для ротации используйте sops updatekeys/rotate.
  • Нет многопользовательской модели: Basic auth + один серверный ключ или ключи в памяти сессий.
  • Открытый текст проходит через сервер (в памяти) — открывайте утилиту по HTTPS или на localhost.
  • Сборка Docker-образа требует интернет (sops/age/pip).
