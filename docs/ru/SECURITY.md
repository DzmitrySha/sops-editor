# Безопасность

Утилита работает с приватными ключами и открытыми секретами. Модель угроз — «внутренний сервер, доверенные разработчики, доступ по HTTPS».

## Что защищено

- **Открытый текст не пишется на диск.** Расшифровка идёт в память процесса/браузера. Временный payload для `sops edit` — файл `0600` в каталоге `0700`, удаляется в `finally`.
- **Резервные копии — только шифротекст.** `/data/backups` не содержит plaintext.
- **Загрузки с компьютера — только шифротекст.** Файл попадает в `/data/uploads/<session>/<token>/`, расшифровывается в памяти, при сохранении снова шифруется. Скачивание отдаёт только файлы из uploads и только если они SOPS-зашифрованы.
- **Ключ UI не персистится.** Хранится в памяти процесса, привязан к `HttpOnly` cookie, TTL 8 ч (sliding). Не попадает в localStorage/логи/ответы API.
- **Пути ограничены корнями.** `realpath` + проверка вхождения; symlink наружу отклоняется; `.git` недоступен.
- **Сохранение атомарно и проверяемо.** SHA-256 исходника, backup, `sops edit`, повторная расшифровка и сверка; при ошибке — restore.
- **SOPS-политика не меняется.** `sops edit` использует мастер-ключи и `encrypted_regex` исходного файла, а не пересобирает файл по текущему `.sops.yaml`.
- **Контейнер:** `read_only`, `cap_drop: ALL`, `no-new-privileges`, запись только в `/data`, `/workspace`, `/tmp`.
- **Веб:** CSP без inline/script CDN, `X-Frame-Options: DENY`, `nosniff`, `no-referrer`, `no-store` для API, SameSite=Strict cookie, проверка Origin на mutating-запросах.

## Обязательные меры для сервера

1. **HTTPS** (Traefik) — иначе ключ и открытый текст идут открытым текстом.
2. **Аутентификация обязательна**, как только порт выходит за loopback: либо Basic auth с длинным случайным `SOPS_EDITOR_AUTH_PASSWORD`, либо `SOPS_EDITOR_AUTH_MODE=header` за OIDC-прокси. При `SOPS_EDITOR_TRUST_PROXY=true` или `SOPS_EDITOR_COOKIE_SECURE=true` контейнер **не стартует** ни с одним из них. `SOPS_EDITOR_AUTH_MODE=none` — только для loopback.
3. **Сетевой доступ**: не публиковать порт в интернет; только Traefik/allowlist.
4. **Ключи**: `keys/age.txt` с правами `600`, отдельный ключ для утилиты, если политика позволяет.
5. **Бэкапы**: `/data/backups` — шифротекст, но всё равно ограничить доступ.
6. **Git-токен** — только read/write к нужным репозиториям (least privilege), не personal admin token.
7. **Логи**: не включайте DEBUG в проде без необходимости; логи содержат пути/размеры, не значения.

## Остаточные риски

- **Сервер видит открытый текст** во время запроса. Это неизбежно для server-side SOPS. Если это неприемлемо — используйте локальный запуск на рабочей машине.
- **Basic auth** не заменяет SSO; используйте `SOPS_EDITOR_AUTH_MODE=header` за OIDC-прокси. В этом режиме заголовок личности доверенный — тот, кто достанет контейнер напрямую, выдаст себя за любого пользователя, поэтому сеть нужно ограничить.
- **XSS**: весь динамический текст рендерится через `textContent`/экранирование; сторонние CDN не используются. Но при добавлении библиотек проверяйте CSP.
- **CSRF**: Basic auth + проверка Origin + SameSite. Мутирующие запросы принимают JSON; cross-site form их не сформирует.
- **DoS**: лимит файла 5 MiB, лимит листинга, таймауты sops/git. Один процесс uvicorn; для больших команд — несколько реплик с общим `/data` (RWO) или внешним storage.
- **Supply chain**: sops/age скачиваются при сборке с pinned версиями и SHA-256; Python-зависимости pinned в `pyproject.toml`. Пересобирайте образ при обновлениях.
- **Резервные копии** не шифруются отдельно; это SOPS-шифротекст, но с теми же получателями, что и оригинал.
- **Git push** выполняется с правами сервера; при compromise контейнера злоумышленник получает доступ к смонтированным репозиториям/ключам. Ограничьте mount и токен.

## Инцидент

1. Остановить контейнер: `docker compose ... down`.
2. Отозвать/сменить age-ключ, git-токен, пароль Basic auth.
3. Проверить `/data/backups` и историю git на несанкционированные изменения.
4. Перевыпустить секреты, если открытый текст мог утечь (логи/дампы/память).
